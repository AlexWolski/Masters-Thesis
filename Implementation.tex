\chapter{Implementation}
\label{chap:implementation}

This section discusses the technical details of our implementation for CSG-CRN. We specify the existing dataset and libraries we used as well as the custom tools we developed.

\section{Dataset~Processing}
\label{sec:dataset_processing}

We use the ShapeNetCore v2 dataset~\cite{Chang2015} for training and performance testing. After preprocessing, it contains~51,641 3D meshes in~54 of the original~55 categories. ShapeNet is commonly used by related work and makes for easy performance comparison.

The dataset needs to be preprocessed to fix or remove bad meshes. A signed distance value can only be computed for watertight manifolds where an interior and exterior volume are clearly defined. We apply the Manifold remeshing algorithm provided by \texttt{Point~Cloud~Utils}~\cite{Williams2022} to seal any holes and remove loose geometry. Then we normalize the mesh by centering it on the origin and scaling it to fit a unit sphere using the \texttt{Mesh~to~SDF}~\cite{Kleineberg2024} tools.

Once the meshes have been cleaned, we extract three types of point samples. Samples directly on the mesh surface are required for the Chamfer Distance and Earth Mover's Distance accuracy metrics. The surface samples are generated using \texttt{Point~Cloud~Utils}, which uses mesh face area weighting to ensure the points are uniformly distributed on the surface. The surface samples can then be used to generate near-surface samples following the method used by DeepSDF~\cite{Park2019}. The surface points are offset by adding 3D Gaussian noise with a standard deviation of~0.1. Lastly, samples are generated uniformly in a unit sphere. \texttt{Point~Cloud~Utils} is used to compute the signed distance to the mesh for both the near-surface and uniform samples. The final dataset we produced contains~16,384 uniform samples,~16,384 near-surface samples, and~30,000 surface samples.


\section{Encoder~Network}
\label{sec:encoder_network_implementation}

As PointNet was originally implemented in \texttt{TensorFlow}, we implement a \texttt{PyTorch} port \texttt{PointNet.pytorch}~\cite{Xia2017}. The code was refactored to allow toggling batch normalization, changing the number of layers, layer sizes, and adding more input features. Batch normalization is always disabled when training in shared parameter mode since each cascade sees a different set of inputs, and the first cascade sees dummy values for the initial reconstruction. The classification and segmentation heads were omitted since we are only interested in the encoder network for CSG-CRN. We expanded the global pooling layer from~1024 features to~3072 features by concatenating max, mean and Avg-TopK~\cite{Ozdemir2023} pooling. The encoder configuration used for the final ShapeNet experiment uses~1024 input samples, encoder convolution layers of size~64,~128, and~1024, transform network convolution layers of size~64,~128, and~1024, and transform network fully-connected layers of size~512 and~256.


\section{Decoder~Network}
\label{sec:decoder_network_implementation}

The decoder network implementation is inspired by~\cite{Paschalidou2019}. A fully-connected MLP network with layers of size~1024 and~512 is used to encode a primitive feature vector. Each of the seven decoder heads has a fully-connected network with layer sizes~128 and~64. All intermediary activation functions are Leaky ReLU with a negative slope of~0.2.

The Shape and Operation heads use a Gumbel-Softmax~\cite{Jang2017} activation function to produce a one-hot vector since our output does not support fractional amounts of a shape or operation. We set~$\tau = 0.5$ to force a one-hot output without killing the gradient. The Translation head uses a Tanh activation to allow for values in the range~$[-1, 1]$. The Rotation head does not need an activation function because the linear output is normalized to produce a valid quaternion. Lastly, the Scale, Blending, and Roundness heads use the Sigmoid activation function to produce values in the range~$[0, 1]$. The minimum scale along each axis is clamped to~0.005 so the model does not produce no-op primitives. And the minimum blending value is clamped to~0.001 since the SDF blending formula breaks at~0. The Operation head may be disabled for some primitives depending on the maximum number of subtract operations configured.


\section{CSG~and~SDF~Processing}
\label{sec:csg_and_sdf_processing}

A custom library was written for processing SDFs and CSG operations. We provide a \texttt{PyTorch} implementation of batched point transforms, batched CSG model sampling, a CSG reconstruction viewer GUI, and an export utility to convert the CSG-CRN output to the \texttt{MagicaCSG} format.
